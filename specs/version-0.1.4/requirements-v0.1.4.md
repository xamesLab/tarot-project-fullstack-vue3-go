# Требования этапа v0.1.4

Дата фиксации: 29 марта 2026.
Статус: `planned`.

## 1. Цель этапа

Собрать ближайший post-`v0.1.3` roadmap в отдельный реализуемый этап `v0.1.4` без инфраструктурного блока следующего порядка.

Этап `v0.1.4` должен:
- закрыть фактическую валидацию backend-этапа `v0.1.2`;
- закрепить dev-tools и UI Kit workflow после `v0.1.3`;
- стабилизировать dev/smoke контур.

Отдельное правило этапа:
- все задачи, связанные с автотестами, откладываются до отдельного явного запроса пользователя;
- все задачи, связанные с файловым хранилищем / внешним storage для assets, откладываются до отдельного явного запроса пользователя.

## 2. Функциональный scope

### 2.1 Закрытие валидации `v0.1.2`

- Поднять backend в рабочем окружении для интеграционной проверки.
- Обеспечить доступность Gateway и корректную callback security конфигурацию.
- Выполнить фактический smoke ask-flow через:
  - `deploy/scripts/smoke-v0.1.2-ask.ps1`
- Обновить статусные документы `v0.1.2` по фактическому результату smoke-прогона.

### 2.2 Dev-tools и UI Kit workflow

- Добавить dev-only индекс `/dev` как каталог внутренних страниц и инструментов.
- Сохранить текущую изоляцию dev-only маршрутов:
  - маршрут должен подключаться только в dev;
  - production не должен регистрировать dev-tools routes.
- Подготовить структуру для расширения dev-only страниц.
- Начать выравнивание продуктовых экранов по токенам и паттернам `/ui-kit`.
- Для всех UI-изменений соблюдать правило `UI Kit First`.

### 2.3 Стабилизация dev/smoke окружения

- Добавить cleanup-скрипт для smoke-данных.
- Покрыть очистку минимум для:
  - пользователей `v011*`, `smoke*`;
  - тестовых колод, созданных smoke-сценариями.
- Описать повторяемый сценарий очистки после smoke-прогонов.

## 3. Вне scope этапа

Этап `v0.1.4` не включает:
- любые автотесты, e2e-тесты, visual regression checks и snapshot-проверки до отдельного явного запроса пользователя;
- вынос изображений в S3-совместимое object storage;
- любое новое файловое хранилище для assets до отдельного явного запроса пользователя;
- backup/restore runbook MongoDB;
- changelog и release notes как отдельный инфраструктурный блок;
- крупную переработку backend API вне задач закрытия `v0.1.2`;
- изменение фоновой системы без отдельного явного запроса.

## 4. Нефункциональные требования

- Не ломать существующие продуктовые сценарии MVP и post-MVP.
- Для frontend-задач соблюдать:
  - `UI Kit First`;
  - `Background Freeze Rule`.
- Dev-only страницы не должны попадать в production-регистрацию маршрутов.
- Новые smoke-команды должны быть задокументированы.

## 5. Критерии приемки

- Интеграционный smoke `v0.1.2` фактически выполнен, а статусные документы обновлены по результату.
- В dev-режиме доступен `/dev`, а в production dev-only страницы не регистрируются.
- В проекте есть cleanup-механизм для smoke-данных и документированный сценарий его запуска.
- Документация `README` и связанные roadmap-документы отражают `v0.1.4` как текущий ближайший этап.
