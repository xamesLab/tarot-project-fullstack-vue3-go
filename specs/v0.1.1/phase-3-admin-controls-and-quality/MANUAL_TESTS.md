# Ручные тесты этапа 3

## Цель проверки

Подтвердить, что AI-функция управляется продуктом, а не только работает технически.

## Чек-лист

### 1. Role policies

1. Проверить AI-доступ для каждой роли.
2. Проверить дневной лимит AI-запросов.
3. Проверить реакцию UI и backend при достижении лимита.

### 2. Admin settings

1. Отключить AI через feature flag.
2. Убедиться, что пользовательский UI корректно скрывает или блокирует AI flow.
3. Включить AI обратно.
4. Изменить model/prompt settings, если они входят в реализацию.

### 3. Metrics

1. Выполнить несколько успешных AI-запросов.
2. Спровоцировать как минимум одну ошибку.
3. Проверить, что агрегированные счётчики и статусы меняются ожидаемо.

### 4. Response quality

1. Проверить поведение при слишком длинном ответе.
2. Проверить поведение при пустом ответе.
3. Проверить, что UI не ломается на неидеальном payload.

## Ожидаемый результат

Этап считается завершённым, если AI-функция управляется лимитами и настройками, а её качество и стоимость можно хотя бы базово контролировать.
