# Этап 3. Admin controls and quality

## Цель этапа

Добавить контроль AI-функции на уровне продукта и улучшить качество работы системы: лимиты, наблюдаемость, prompt governance и UX ошибок.

## Что должно быть реализовано

### 1. Role policies для AI

- добавить AI-лимиты по ролям
- определить, кому AI доступен:
  - `Seeker`
  - `Adept`
  - `Master`
  - `Keeper`
- определить дневной лимит AI-запросов на пользователя

Текущий статус:

- реализовано `ai_enabled` и `ai_daily_limit` в `role_policies`
- backend уже применяет role-based AI gating и дневной лимит в `/api/ask`
- admin UI уже умеет редактировать эти поля

### 2. Admin settings

- feature flag для включения/выключения AI
- настройка основного model id или policy-level model override
- prompt template/version management на уровне backend/admin settings
- опционально: отдельные тексты system prompt для EN и RU

Текущий статус:

- реализован глобальный `ai_enabled` в `admin_settings`
- backend учитывает global feature flag перед direct AI-вызовом
- admin settings page уже позволяет включать и выключать AI без правок env

### 3. Наблюдаемость

- добавить базовые AI-метрики:
  - количество запросов
  - success/failure
  - latency
  - token usage
- добавить admin visibility для агрегированных AI-метрик
- не показывать секреты и сырые провайдерские детали в админке

### 4. Качество ответа

- предусмотреть structured output там, где это поддерживается выбранной моделью
- если structured output недоступен, валидировать и нормализовать plaintext/JSON response server-side
- ввести защиту от пустых, слишком длинных и плохо сформированных ответов

### 5. Дополнительные улучшения проекта

В этой версии стоит включить два улучшения общего качества:

- улучшить логирование и correlation id для сложных backend-запросов
- улучшить product resilience: reuse AI-ответов и защита от лишних повторных расходов при рефреше/дабл-клике

## Результат этапа

После этапа AI-функция перестаёт быть просто “работающим запросом” и становится управляемой product capability.

## Основные риски этапа

- слишком раннее усложнение админки
- несогласованность AI-лимитов с existing role-policy model
- нестабильный output format от разных моделей
- отсутствие прозрачности по ошибкам и затратам

## Критерии готовности

- AI-лимиты по ролям работают
- AI feature flag управляется централизованно
- prompt/model governance задокументированы
- admin видит базовые AI-метрики
- response quality защищена в коде и контракте
