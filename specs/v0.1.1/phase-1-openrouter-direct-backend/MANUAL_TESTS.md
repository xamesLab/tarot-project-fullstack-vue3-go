# Ручные тесты этапа 1

## Цель проверки

Подтвердить, что backend действительно получает AI-ответ через `OpenRouter` и корректно обрабатывает рабочие и ошибочные сценарии.

## Чек-лист

### 1. Базовый happy path

1. Выполнить `POST /api/ask` для доступного пользователю чтения.
2. Убедиться, что backend создаёт запись `ask_request`.
3. Убедиться, что ответ содержит статус и результат в ожидаемом формате.
4. Проверить `GET /api/ask/:request_id` для того же запроса.
5. Проверить, что результат является компактной интерпретацией и не превышает ожидаемый лимит длины.

### 2. Авторизация и доступ

1. Вызвать `POST /api/ask` без токена.
2. Вызвать `POST /api/ask` с чужим `reading_id`.
3. Проверить, что доступ запрещается без утечки внутренних деталей.

### 3. Ошибки провайдера

1. Проверить поведение при невалидном ключе.
2. Проверить поведение при таймауте провайдера.
3. Проверить поведение при rate limit.
4. Проверить поведение при пустом или невалидном ответе модели.

### 4. Повторные запросы

1. Повторить запрос для одного и того же чтения.
2. Убедиться, что поведение соответствует задокументированному правилу reuse/regenerate.

### 5. Prompt quality

1. Проверить, что для `Card of the Day` в запросе участвует только открытая карта и язык пользователя.
2. Проверить, что для `3-card spread` в запросе участвуют все карты и их позиции.
3. Проверить, что модель не возвращает длинный ответ, список или лишние служебные фразы.

### 6. Диагностика

1. Проверить AI health endpoint.
2. Убедиться, что в health/ошибках нет секретных значений.

## Ожидаемый результат

Этап считается завершённым, если AI backend flow стабильно работает через `OpenRouter`, а ошибки провайдера обрабатываются без утечки чувствительных данных.
