# Этап 2. AI reading experience

## Цель этапа

Подключить AI-интерпретации к пользовательскому интерфейсу так, чтобы они органично дополняли существующий reading flow и не ломали `UI Kit`/дизайн-систему.

## Что должно быть реализовано

### 1. Пользовательский сценарий

- после открытия `Card of the Day` или полного открытия `3-card spread` frontend должен инициировать AI-запрос к backend
- сценарий должен работать как минимум для:
  - `Card of the Day`
  - `3-card spread`
- AI flow не должен подменять базовую карточную механику и существующие тексты полностью
- результат AI должен отображаться в уже существующем блоке `Значение расклада`
- не нужно создавать отдельный экран или отдельную страницу под AI interpretation

### 2. Frontend integration

- добавить service layer для `/api/ask`
- добавить store/state для AI-запросов
- поддержать состояния:
  - idle
  - loading
  - completed
  - failed
- сохранять привязку интерпретации к конкретному reading
- обеспечивать обновление содержимого блока `Значение расклада` после успешного AI-ответа

### 3. UI/UX

- использовать текущий блок `Значение расклада` как контейнер для AI-ответа
- если до AI-запроса блок уже содержит базовую краткую трактовку, определить правило замены или обогащения и придерживаться его консистентно
- локализовать тексты EN/RU
- поддержать mobile behavior и loading/error states

### 4. Reuse результата

- при повторном открытии чтения уже полученная AI-интерпретация должна восстанавливаться из сохранённого поля reading без лишнего запроса, если продуктовая логика не требует regeneration
- UI должен различать:
  - ещё не запрашивали
  - запрос в процессе
  - результат готов
  - генерация не удалась

### 5. Product-level ограничения

- AI не должен быть доступен до полного раскрытия расклада, если это выбранное правило
- AI-интерпретация не должна появляться для чужих чтений
- UI должен явно отделять базовую трактовку карт от AI interpretation layer

## Дополнительные улучшения проекта

В рамках этого этапа стоит добавить два улучшения:

- улучшить блок истории, чтобы у чтений было понятное состояние наличия AI-интерпретации
- улучшить UX error-recovery: кнопка повторной попытки и более дружелюбные сообщения ошибок провайдера

## Результат этапа

После этапа пользователь получает рабочий AI flow поверх уже существующего reading experience.

## Основные риски этапа

- перегрузка интерфейса лишними AI-блоками
- расхождение боевого UI и `UI Kit`
- неясное различие между базовой трактовкой и AI interpretation
- лишние повторные запросы из-за плохого восстановления состояния

## Критерии готовности

- AI flow доступен для нужных reading screens
- loading/error/completed states отрисованы консистентно
- EN/RU и mobile поддержаны
- повторное открытие чтения восстанавливает корректное AI-состояние
