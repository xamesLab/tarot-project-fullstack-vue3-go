# Ручные тесты этапа 4

## Цель проверки

Подтвердить, что административный контур безопасен, доступен только роли `keeper` и покрывает основные операции управления системой.

## Чек-лист

### 1. Контроль доступа

1. Войти обычным пользователем.
2. Попробовать открыть `/admin`.
3. Убедиться, что доступ запрещён.
4. Войти пользователем с ролью `keeper`.
5. Проверить, что admin-раздел становится доступен.

### 2. Admin dashboard

1. Открыть admin dashboard.
2. Проверить наличие метрик по пользователям, чтениям и колодам.
3. Убедиться, что страница грузится без ошибок.

### 3. Users

1. Открыть список пользователей.
2. Выполнить поиск по username или email.
3. Применить фильтр по роли.
4. Изменить роль тестового пользователя.
5. Проверить, что роль сохранилась.
6. Если реализовано отключение аккаунта, проверить disable flow.

### 4. Role policies

1. Открыть страницу политик ролей.
2. Изменить лимит для одной роли.
3. Сохранить изменения.
4. Проверить, что новые значения возвращаются после перезагрузки.

### 5. Settings

1. Открыть глобальные настройки.
2. Включить и выключить maintenance mode.
3. Изменить maintenance message и default role.
4. Сохранить изменения и убедиться, что они применились.

### 6. Decks

1. Создать новую колоду с валидным ZIP.
2. Проверить, что колода появляется в списке.
3. Проверить, что статус доходит до `done`.
4. Загрузить заведомо невалидный ZIP.
5. Убедиться, что приходит понятная ошибка и мусорные файлы не остаются в рабочем состоянии.

### 7. Локализация

1. Переключить admin-раздел на русский.
2. Пройти ключевые страницы и убедиться, что интерфейс локализован.

## Ожидаемый результат

Этап считается завершённым, если `keeper` может управлять системой через UI, а неавторизованные и неподходящие роли в admin-контур не попадают.
