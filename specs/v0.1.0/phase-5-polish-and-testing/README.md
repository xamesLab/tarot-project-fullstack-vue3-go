# Этап 5. Полировка и тестирование

## Цель этапа

Довести MVP до состояния, пригодного для релиза: привести интерфейс к консистентному виду, закрыть ошибки, проверить адаптивность, accessibility, производительность и устойчивость к edge cases.

## Что должно быть реализовано

### 1. Завершение UI Kit

- проверить все компоненты на консистентность
- выровнять цвета, типографику, отступы, скругления и тени
- убедиться, что UI Kit отражает фактическое состояние интерфейса

### 2. Адаптивность

- проверить экраны на `375px`, `768px`, `1280px+`
- привести dashboard, history, admin tables и modals к мобильному поведению
- проверить touch interactions

### 3. Accessibility

- добавить ARIA labels
- настроить keyboard navigation
- добавить focus states
- проверить контрастность на базовом уровне `WCAG AA`

### 4. Производительность

- оптимизировать изображения
- внедрить lazy loading
- настроить code splitting
- проверить время загрузки страниц
- проверить latency основных API

### 5. Ошибки и edge cases

- network errors
- timeout errors
- `500` ответы backend
- невалидный JWT
- ошибки БД
- смена timezone при активной карте дня
- точное достижение лимита раскладов
- невалидный deck ZIP
- обращение к удалённой колоде
- clock rollback

### 6. Финальная ручная приёмка

- new user journey
- returning user journey
- admin journey
- cross-browser проверки
- проверки i18n
- проверки themes

## Результат этапа

После завершения этапа продукт должен быть стабилен, визуально целостен и предсказуем в основных и пограничных сценариях использования.

## Критерии готовности

- интерфейс адаптивен
- критические баги исправлены
- ручные сценарии пройдены
- ошибки отображаются понятно и локализованно
- performance targets достигнуты или зафиксированы как допустимые отклонения
