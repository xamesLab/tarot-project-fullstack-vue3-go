# Промежуточный этап. UI Kit Foundation

> **Статус:** выполнено  
> **Кратко:** UI Kit доработан на основе `specs/UI/UIKit.vue`, переведён в роль design-system reference, оставлен публичным и автономным, а доступ к нему ограничен только dev-режимом; в `.codex` зафиксировано правило опираться на UI Kit и `specs/docs/DESIGN_SYSTEM.md` при frontend-разработке по умолчанию.

## Цель этапа

Подготовить полноценную страницу `UI Kit` как источник истины для визуальной системы и библиотеки будущих frontend-компонентов проекта `Tarot Daily`.

Этот этап выполняется до основной реализации `phase-2-core-frontend`, потому что дальнейшая frontend-разработка должна опираться на утверждённую дизайн-систему, а не собираться стихийно по страницам.

## Основная задача

Нужно доработать страницу `UI Kit`, используя шаблон из:

- `specs/UI/UIKit.vue`

Итоговая страница должна стать:

- демонстрацией дизайн-системы
- библиотекой базовых UI-паттернов
- эталоном визуального языка для дальнейшей frontend-разработки

## Обязательные требования

### 1. Источник шаблона

- за основу берётся `specs/UI/UIKit.vue`
- агент не должен игнорировать этот шаблон и придумывать UI Kit с нуля
- допускается адаптация шаблона под архитектуру текущего frontend, но без потери его роли как design source

### 2. Роль UI Kit в проекте

UI Kit должен быть оформлен как:

- центральная страница дизайн-системы
- библиотека примитивов и базовых состояний
- reference implementation для будущих страниц и компонентов

### 3. Автономность страницы

Страница должна быть полностью автономной:

- доступна без авторизации
- не зависит от пользовательской сессии
- не требует backend-данных для отображения
- не зависит от бизнес-логики других страниц
- может использовать только локальные mock/demo данные

### 4. Ограничение по окружению

Страница должна быть доступна только в режиме разработки:

- доступна по dev-route
- в production не должна открываться
- при попытке перехода в production должен срабатывать redirect или блокировка

### 5. Содержательное наполнение

UI Kit должен покрывать как минимум:

- typography
- color palette / design tokens
- buttons
- inputs
- selects
- modals
- cards / surfaces
- layout primitives
- interactive states:
  - default
  - hover
  - focus
  - disabled
  - error
  - loading, если применимо

### 6. Требование к дальнейшей разработке

После завершения этого этапа все последующие frontend-этапы должны опираться на UI Kit как на основной reference, если пользователь явно не указал другой источник или не потребовал отдельный редизайн.

Центральная фиксация этих решений вынесена в:

- `specs/docs/DESIGN_SYSTEM.md`

## Ожидаемый результат

После завершения этапа в проекте должна существовать dev-only страница UI Kit, которая:

- визуально соответствует шаблону из `specs/UI/UIKit.vue`
- встроена в текущий frontend
- работает автономно
- служит опорой для дальнейшей разработки компонентов и страниц

## Риски этапа

- сделать UI Kit просто красивой страницей, а не рабочим reference source
- потерять связь с шаблоном из `specs/UI/UIKit.vue`
- допустить зависимость UI Kit от auth/backend
- начать строить frontend-страницы вне design-system подхода

## Критерии готовности

- UI Kit доступен в dev-режиме без авторизации
- UI Kit недоступен в production
- страница автономна и не требует API
- шаблон `specs/UI/UIKit.vue` явно использован как основа
- базовые UI-секции и состояния оформлены и пригодны как source of truth
- в настройках агента проекта зафиксировано правило опираться на UI Kit при frontend-разработке по умолчанию
- центральный design-system reference зафиксирован в `specs/docs/DESIGN_SYSTEM.md`
