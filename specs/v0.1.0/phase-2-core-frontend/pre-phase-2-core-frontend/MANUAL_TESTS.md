# Ручные тесты промежуточного этапа UI Kit Foundation

## Цель проверки

Подтвердить, что UI Kit стал рабочим design-system entry point и может использоваться как основной ориентир для дальнейшей frontend-разработки.

## Чек-лист

### 1. Доступность в dev-режиме

1. Запустить frontend в режиме разработки.
2. Открыть маршрут UI Kit.
3. Убедиться, что страница открывается без авторизации.
4. Убедиться, что UI Kit не требует токена и не зависит от login flow.

### 2. Недоступность в production

1. Собрать production build.
2. Проверить поведение при переходе на маршрут UI Kit.
3. Убедиться, что страница не доступна в production и происходит redirect или блокировка.

### 3. Автономность

1. Открыть UI Kit без поднятого backend, если это возможно в локальной конфигурации.
2. Убедиться, что страница всё равно рендерится.
3. Проверить, что для отображения не нужны API-запросы.

### 4. Соответствие шаблону

1. Сравнить реализованную страницу с `specs/UI/UIKit.vue`.
2. Убедиться, что ключевые визуальные разделы и структура сохранены.
3. Проверить, что адаптация под текущий frontend не разрушила исходную идею страницы.

### 5. Покрытие дизайн-системы

1. Проверить разделы typography и colors.
2. Проверить кнопки, инпуты, select и modal shell.
3. Проверить card/surface patterns.
4. Проверить наличие базовых visual states: hover, focus, disabled, error.

### 6. Практическая пригодность

1. Оценить, можно ли использовать UI Kit как reference для будущих компонентов.
2. Убедиться, что базовые стили и паттерны можно переносить в реальные страницы без переизобретения.

### 7. Правило для агента

1. Проверить проектные настройки агента.
2. Убедиться, что в них зафиксировано правило:
   frontend по умолчанию должен опираться на UI Kit, если не указано иное.

## Ожидаемый результат

Этап считается завершённым, если UI Kit стал автономной dev-only дизайн-системой и официальным ориентиром для дальнейшей frontend-разработки.
