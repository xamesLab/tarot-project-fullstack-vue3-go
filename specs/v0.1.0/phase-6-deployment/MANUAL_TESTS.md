# Ручные тесты этапа 6

## Цель проверки

Подтвердить, что production-окружение готово к использованию реальными пользователями.

## Чек-лист

### 1. Доступность

1. Открыть production URL в браузере.
2. Убедиться, что frontend загружается по HTTPS.
3. Проверить валидность SSL-сертификата.

### 2. Backend smoke tests

1. Проверить health или gateway stub endpoint.
2. Зарегистрировать тестового пользователя.
3. Выполнить логин.
4. Сгенерировать `Card of the Day`.
5. Сгенерировать `3-card spread`.

### 3. Frontend smoke tests

1. Пройти пользовательский путь через UI.
2. Проверить загрузку изображений карт и колод.
3. Проверить theme switch.
4. Проверить language switch.

### 4. Admin smoke tests

1. Войти как `keeper`.
2. Открыть admin dashboard.
3. Проверить список пользователей.
4. Проверить хотя бы одну безопасную admin-операцию.

### 5. Uploads и proxy

1. Убедиться, что `/api` корректно проксируется.
2. Убедиться, что статические файлы колод доступны.

### 6. Monitoring

1. Проверить, что backend пишет логи.
2. Проверить, что uptime monitoring видит сервис как доступный.

### 7. Post-launch наблюдение

1. В течение первых `24` часов проверять логи и доступность.
2. Зафиксировать все критические ошибки.
3. Убедиться, что блокирующие production-баги либо отсутствуют, либо устранены.

## Ожидаемый результат

Этап считается завершённым, если production доступен, основные сценарии проходят успешно, а команда видит состояние системы после запуска.
