# Ручные тесты этапа 3

## Цель проверки

Подтвердить, что основной tarot-функционал работает стабильно и соответствует доменной логике из документации.

## Чек-лист

### 1. Card of the Day

1. Зайти новым пользователем на dashboard.
2. Сгенерировать `Card of the Day`.
3. Убедиться, что карта отображается с именем и интерпретацией.
4. Попробовать сгенерировать карту повторно в тот же учётный день.
5. Убедиться, что backend или UI запрещает повторную выдачу.

### 2. Детерминированность

1. Сохранить результат `Card of the Day`.
2. Перезагрузить страницу и убедиться, что возвращается та же карта.
3. Если есть возможность повторить запрос напрямую к API без смены даты, подтвердить, что карта не меняется.

### 3. 3-card spread

1. Сгенерировать расклад.
2. Убедиться, что отображаются три разные карты.
3. Проверить наличие интерпретаций и лимита оставшихся раскладов.
4. Повторить до достижения дневного лимита.
5. Убедиться, что кнопка генерации блокируется или приходит ожидаемая ошибка.

### 4. Проверка ролей

1. Выполнить сценарий для `seeker`.
2. При наличии тестовых ролей повторить сценарий для `adept`, `master`, `keeper`.
3. Проверить, что лимиты и срок истории соответствуют политике роли.

### 5. История

1. Перейти на `/history`.
2. Проверить отображение записей по дате.
3. Применить фильтр по типу чтения.
4. Переключить страницу пагинации, если данных достаточно.
5. Развернуть один элемент истории и проверить детали.

### 6. Timezone edge cases

1. Проверить поведение около `02:59`.
2. Проверить поведение в `03:00`.
3. Изменить timezone пользователя и проверить, меняется ли доступность дневной карты согласно правилам.

### 7. Локализация

1. Переключить язык на русский.
2. Проверить названия карт, тексты кнопок, сообщения об ошибке и историю.
3. Переключить обратно на английский и убедиться, что данные остаются согласованными.

## Ожидаемый результат

Этап считается завершённым, если пользователь может получать и просматривать чтения без нарушения лимитов, timezone-логики и retention-правил.
