# Ручные тесты этапа 1

## Цель проверки

Подтвердить, что backend готов обслуживать auth и profile сценарии и корректно работает с часовыми поясами.

## Чек-лист

### 1. Регистрация

1. Отправить запрос регистрации с валидными данными.
2. Убедиться, что пользователь создаётся.
3. Проверить, что в ответе приходит JWT.
4. Проверить, что новому пользователю назначается роль `seeker`.

### 2. Негативные сценарии регистрации

1. Повторно зарегистрировать тот же email.
2. Убедиться, что backend возвращает ошибку уникальности.
3. Проверить слабый пароль.
4. Проверить невалидный timezone.
5. Проверить занятый username.

### 3. Логин

1. Выполнить логин с корректными данными.
2. Подтвердить выдачу токена.
3. Выполнить логин с неверным паролем.
4. Убедиться, что возвращается ошибка авторизации.

### 4. Защищённые endpoints

1. Вызвать `GET /api/me` без токена.
2. Убедиться, что приходит `401`.
3. Повторить запрос с валидным токеном.
4. Убедиться, что профиль возвращается успешно.

### 5. Обновление профиля и настроек

1. Изменить username.
2. Изменить timezone.
3. Изменить language и theme.
4. Проверить, что обновлённые значения возвращаются в последующем `GET /api/me`.

### 6. Проверка JWT

1. Отправить запрос с испорченным токеном.
2. Убедиться, что доступ запрещён.
3. Если реализован срок жизни токена, проверить реакцию на истёкший токен.

### 7. Проверка timezone-логики

1. Протестировать вычисление `accounting day` для времени `02:59`.
2. Протестировать вычисление `accounting day` для времени `03:00`.
3. Повторить сценарий для нескольких timezone, например `UTC`, `Europe/Amsterdam`, `America/New_York`.

## Ожидаемый результат

Этап считается завершённым, если auth и profile сценарии устойчивы, а timezone-расчёты корректны на граничных значениях.
