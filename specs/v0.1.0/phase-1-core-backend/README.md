# Этап 1. Базовый backend

> **Статус:** выполнено  
> **Кратко:** реализованы регистрация, логин, JWT auth middleware, `GET /api/me`, `PATCH /api/me/profile`, `PATCH /api/me/settings`, CORS, user indexes и timezone utilities; backend собирается, `go test ./...` проходит, основные ручные HTTP-проверки пройдены.

## Цель этапа

Построить фундамент backend-части MVP: аутентификацию, профиль пользователя, базовые модели и репозитории, а также корректную timezone-логику для расчёта учётного дня.

## Что должно быть реализовано

### 1. Аутентификация

- регистрация по email, username, password и timezone
- логин по email и password
- выпуск JWT после успешной аутентификации
- хранение в JWT: `user_id`, `role`, `timezone`
- bcrypt-хеширование паролей
- базовая валидация пароля и timezone

### 2. Пользователь и профиль

- получение данных текущего пользователя через `GET /api/me`
- обновление профиля через `PATCH /api/me/profile`
- обновление настроек через `PATCH /api/me/settings`
- проверка уникальности username
- поддержка настроек:
  - timezone
  - language
  - theme
  - selected deck
  - selected back

### 3. Middleware и безопасность

- auth middleware для проверки JWT
- role middleware для защиты маршрутов по ролям
- CORS-конфигурация
- единый формат ошибок для невалидных и неавторизованных запросов

### 4. Доступ к данным

- репозиторий пользователей
- репозиторий карт
- базовые структуры моделей для auth и profile flows

### 5. Временная логика

- `GetAccountingDate(timezone)`
- `GetNextResetTime(timezone)`
- `ValidateTimezone(tz)`
- учёт граничного условия `02:59` против `03:00`

## API, которые должны появиться

- `POST /api/auth/register`
- `POST /api/auth/login`
- `GET /api/me`
- `PATCH /api/me/profile`
- `PATCH /api/me/settings`

## Результат этапа

К концу этапа frontend уже может:

- зарегистрировать пользователя
- залогинить пользователя
- получить его профиль
- изменить настройки
- безопасно передавать JWT в последующие запросы

## Основные риски этапа

- ошибки в timezone-валидации
- проблемы с уникальностью username и email
- неверная обработка невалидных токенов
- пограничные баги около `03:00`

## Критерии готовности

- регистрация и логин работают end-to-end
- JWT корректно выдаётся и валидируется
- защищённые endpoints требуют авторизации
- профиль и настройки обновляются
- расчёт `accounting day` проходит edge cases
