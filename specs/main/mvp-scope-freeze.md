# MVP Scope Freeze: Tarot Daily

Документ фиксирует неизменяемую базу MVP для реализации.
Источник: `specs/main/PRD.md`, `specs/main/architecture.md`, `specs/main/project-structure.md`.

## 1. Цель MVP
Запустить локально рабочее веб-приложение, где пользователь после регистрации и входа получает:
- карту дня;
- два расклада (A: 3 карты, B: 5 карт);
- интерпретации карт по состоянию `open`/`closed`.

## 2. In Scope (обязательно для MVP)
- Аутентификация: регистрация, вход, выход, `JWT`.
- Роли: `user` и `admin`.
- Личный кабинет пользователя.
- Ежедневная генерация контента по таймзоне пользователя с границей суток в `03:00`.
- `Карта дня` фиксируется на дату; расклады могут перегенерироваться в рамках лимита роли.
- Настройки пользователя:
  - таймзона (по умолчанию `UTC+00:00`);
  - выбор темы колоды (`deckTheme`).
- Админ-страница `/admin`:
  - просмотр тем колод;
  - добавление темы колоды.
- Базовая адаптивность интерфейса (mobile-first).
- Локальный запуск проекта в dev.

## 3. Out of Scope (не делаем в MVP)
- Production deployment и production-grade инфраструктура.
- Платежи, подписки, CRM.
- Обязательная AI-генерация интерпретаций.
- Полноценная CMS.
- Полноценный UI истории (данные можно хранить на уровне API/БД).

## 4. Зафиксированные бизнес-правила
- Card of Day: `1` карта.
- Spread A: `3` карты без повторов внутри расклада.
- Spread B: `5` карт без повторов внутри расклада.
- Повторы между блоками Card of Day / Spread A / Spread B в один день допустимы.
- Для каждой карты состояние выбирается случайно: `open` или `closed`.
- Интерпретация выбирается по состоянию карты.
- Дата определяется по таймзоне пользователя; если не задана, используется `UTC+00:00`.
- Сброс суток для генерации: `03:00` по таймзоне пользователя.
- Лимиты генераций раскладов:
  - `user` по умолчанию: `10` в сутки;
  - `admin`: без лимита;
  - для кастомных ролей лимит задается в `role_policies`.

## 5. Зафиксированный API-контур MVP
- `POST /api/auth/register`
- `POST /api/auth/login`
- `GET /api/me`
- `PATCH /api/me/settings`
- `GET /api/reading/today`
- `POST /api/reading/generate`
- `GET /api/deck-themes`
- `GET /api/admin/deck-themes` (admin only)
- `POST /api/admin/deck-themes` (admin only)
- `GET /api/admin/roles` (admin only)
- `POST /api/admin/roles` (admin only)
- `PATCH /api/admin/users/role` (admin only)

## 6. Зафиксированный data-контур MVP
- Коллекции MongoDB:
  - `users`
  - `cards`
  - `daily_readings`
  - `deck_themes`
  - `role_policies`
- Обязательные индексы:
  - `users.login` unique
  - `daily_readings(userId, date)` unique

## 7. Definition of Done для MVP
- Пользователь может зарегистрироваться и войти.
- После входа видит карту дня + 2 расклада (3 и 5 карт).
- Карты в раскладах без повторов внутри каждого расклада.
- Для каждой карты корректно отображаются: изображение, описание, интерпретация.
- На один день возвращается одна и та же `карта дня`; на новый день генерируется новая.
- Расклады генерируются в рамках дневного лимита роли пользователя.
- Пользователь может менять таймзону и тему колоды.
- Админ-панель доступна только `admin`.
- `admin` может добавить новую тему колоды.
- Интерфейс корректно работает на мобильном экране.
- Проект воспроизводимо запускается локально.

## 8. Правило изменения scope
Любое расширение сверх этого документа считается post-MVP и оформляется отдельным изменением PRD/roadmap.
