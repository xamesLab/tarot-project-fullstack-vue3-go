# PRD: Tarot Daily Web App (MVP)

## 1. Обзор продукта

### 1.1 Название (рабочее)
Tarot Daily

### 1.2 Цель
Развлекательное веб-приложение в тематике Таро, где пользователь ежедневно получает:
- 2 расклада таро
- 1 карту дня

Для каждой карты отображаются:
- изображение
- описание
- интерпретация/предсказание

### 1.3 Бизнес-проблема
Целевая аудитория хочет быстро получать персонализированный мистический контент 1-2 раза в день в удобном личном кабинете.

## 2. Целевая аудитория

- Девушки и женщины, увлекающиеся мистикой и таро.
- Поведенческий сценарий: короткие сессии 1-2 раза в день ради прогноза/развлекательного контента.

## 3. Область MVP

### 3.1 Входит в MVP
- Регистрация/авторизация по логину и паролю.
- Личный кабинет пользователя.
- Роли пользователей: `user`, `admin`.
- Админка (страница администратора), доступная только роли `admin`.
- Генерация и показ:
  - 2 видов расклада таро
  - 1 карты дня
- Случайный выбор карт из колоды.
- Поддержка состояния карты: `open` или `closed`.
- Отображение изображения карты, описания и интерпретации.
- Выбор пользователем набора изображений карт (для MVP - заглушки).
- Адаптивный интерфейс (mobile-first).
- Локальный запуск в dev-среде.

### 3.2 Не входит в MVP
- Прод-развертывание и инфраструктура production-grade.
- Платежи, подписки, CRM-интеграции.
- Обязательная AI-генерация (низкий приоритет, как опция).
- Полноценная CMS: в MVP админ может только добавлять варианты изображений (базовый минимум).

## 4. Пользовательские сценарии

1. Как новый пользователь, я хочу зарегистрироваться по логину/паролю, чтобы пользоваться личным кабинетом.
2. Как авторизованный пользователь, я хочу открыть личный кабинет и получить карту дня, чтобы увидеть прогноз.
3. Как авторизованный пользователь, я хочу получить 2 расклада и видеть выпавшие карты с трактовкой.
4. Как пользователь, я хочу выбрать стиль/набор изображений карт в ЛК.
5. Как пользователь, я хочу возвращаться 1-2 раза в день и получать новый контент.
6. Как администратор, я хочу открыть админку и добавить новые варианты изображений карт.

## 5. Функциональные требования

### 5.1 Аутентификация и роли
- Регистрация:
  - уникальный логин
  - пароль (хранится как хеш)
- Вход по логину/паролю.
- Выход из аккаунта.
- Сессия через JWT (или аналогичный токен-механизм).
- Роль назначается в профиле пользователя:
  - по умолчанию `user`
  - `admin` создается/назначается вручную на этапе dev

### 5.2 Личный кабинет пользователя
- Стартовый экран после входа:
  - карта дня (одна карта)
  - два расклада (тип A и тип B для MVP)
- Настройки пользователя:
  - таймзона (по умолчанию `UTC+00:00`)
  - выбранный набор изображений карт (`deckTheme`)
- Блок с датой последней генерации.
- При повторном входе в тот же день показывается тот же результат.

### 5.3 Админка (MVP)
- Отдельная страница `/admin`.
- Доступ только для роли `admin` (backend + frontend guard).
- MVP-функции админки:
  - добавление нового варианта набора изображений карт
  - просмотр списка доступных наборов
- Пользователь без роли `admin` получает 403/редирект.

### 5.4 Контент карт
- В системе есть справочник карт колоды (минимум: 78 карт).
- Для каждой карты:
  - `name`
  - `description`
  - `interpretationOpen`
  - `interpretationClosed`
- Изображения зависят от выбранного набора (`deckTheme`), в MVP можно использовать заглушки.
- Возможность в будущем подменить/дополнить интерпретации AI-сервисом.

### 5.5 Правила генерации
- Карта дня: 1 карта.
- Расклад A: 3 карты.
- Расклад B: 5 карт.
- Выбор карт случайный из колоды без повторов внутри одного расклада.
- Между разными блоками на один день повторы допустимы (упрощение MVP).
- Для каждой выпавшей карты случайно задается состояние: `open` или `closed`.
- Интерпретация выбирается по состоянию карты.
- Дневная логика:
  - контент фиксируется на текущую дату по таймзоне пользователя из ЛК
  - если таймзона не задана, используется `UTC+00:00`
  - на следующий день по этой таймзоне генерируется новый результат

### 5.6 История (минимум)
- Хранить результаты по датам для текущего пользователя.
- В UI MVP можно показывать только текущий день (история готова на уровне БД/API для расширения).

## 6. Нефункциональные требования

- Адаптивность: корректная работа на мобильных экранах (приоритет).
- Производительность: загрузка ключевого экрана до 2-3 секунд в локальном dev при типовом объеме данных.
- Безопасность (базовая):
  - хеширование паролей (bcrypt/argon2)
  - базовая валидация входных данных
  - защита приватных endpoint через auth middleware
  - проверка роли `admin` для админских endpoint
- Кодовая база должна быть простой для поддержки небольшой командой.

## 7. Технический стек и архитектура

### 7.1 Frontend
- Vue 3
- Pinia
- Vue Router
- Адаптивная верстка (mobile-first)

### 7.2 Backend
- Go
- Gin
- REST API
- JWT auth + role-based access middleware

### 7.3 Database
- MongoDB
- Коллекции: `users`, `cards`, `daily_readings`, `deck_themes`

### 7.4 Локальная разработка
- Запуск локально (без production deployment)
- Желательно docker-compose для MongoDB + backend + frontend (опционально для MVP)

## 8. Модель данных (черновая)

### 8.1 users
- `_id`
- `login` (unique)
- `passwordHash`
- `role` (`user` | `admin`)
- `timezone` (IANA или фиксированный UTC offset, default `UTC+00:00`)
- `deckThemeId` (выбранный вариант изображений)
- `createdAt`
- `updatedAt`

### 8.2 cards
- `_id`
- `name`
- `arcanaType` (major/minor)
- `description`
- `interpretationOpen`
- `interpretationClosed`

### 8.3 deck_themes
- `_id`
- `name`
- `isPlaceholder` (bool)
- `assets` (mapping: `cardCode -> imageUrl`)
- `createdBy` (admin userId)
- `createdAt`

### 8.4 daily_readings
- `_id`
- `userId`
- `date` (YYYY-MM-DD по таймзоне пользователя)
- `timezoneUsed`
- `cardOfDay` (`cardId`, `state`)
- `spreadA` (array of `{ cardId, state }`)
- `spreadB` (array of `{ cardId, state }`)
- `generatedAt`
- unique index: (`userId`, `date`)

## 9. API (черновой контракт)

- `POST /api/auth/register`
- `POST /api/auth/login`
- `GET /api/me`
- `PATCH /api/me/settings` (timezone, deckTheme)
- `GET /api/reading/today`
  - Возвращает карту дня + 2 расклада на текущую дату
  - Если записи за дату нет, создает и возвращает
- `GET /api/deck-themes` (доступно пользователю, чтобы выбрать тему)
- `POST /api/admin/deck-themes` (только `admin`)
- `GET /api/admin/deck-themes` (только `admin`)

Пример `GET /api/reading/today` response:

```json
{
  "date": "2026-03-07",
  "timezoneUsed": "UTC+03:00",
  "cardOfDay": {
    "id": "card_10",
    "name": "Wheel of Fortune",
    "state": "open",
    "imageUrl": "/themes/default/wheel.jpg",
    "description": "...",
    "interpretation": "..."
  },
  "spreadA": [],
  "spreadB": []
}
```

## 11. Метрики успеха MVP

- Функциональный критерий: продукт полностью запускается локально и проходит основной user flow.
- Технический критерий: авторизация + выдача ежедневного контента работают стабильно.
- Поведенческий критерий (на этапе ручного теста): пользователь может возвращаться 1-2 раза в день и видеть фиксированный результат за дату.

## 12. Критерии приемки

1. Пользователь может зарегистрироваться и войти по логину/паролю.
2. После входа пользователь видит карту дня и 2 расклада (3 и 5 карт).
3. Карты выбираются случайно и без повторов внутри каждого расклада.
4. Каждая карта имеет состояние `open` или `closed`, и отображается соответствующая интерпретация.
5. Для каждой карты отображаются изображение, описание и интерпретация.
6. При повторном входе в тот же день данные те же; на следующий день (по таймзоне пользователя) обновляются.
7. Пользователь может изменить таймзону в ЛК; по умолчанию `UTC+00:00`.
8. Пользователь может выбрать доступный набор изображений карт.
9. Админка доступна только роли `admin`; обычный пользователь не имеет доступа.
10. Админ может добавить новый вариант набора изображений.
11. Интерфейс корректно отображается на мобильном разрешении.
12. Проект запускается локально в dev.

## 13. План развития после MVP

- Подключение AI-генерации интерпретаций (feature-flag).
- Расширение админки до полноценного управления контентом карт.
- История раскладов в UI.
- Настройка тем/колод/персонализации.

## 14. Зафиксированные решения

1. Состояния карт в MVP: `open` и `closed`.
2. Форматы раскладов: A = 3 карты, B = 5 карт.
3. Дневная генерация считается по таймзоне из ЛК, по умолчанию `UTC+00:00`.
4. Изображения карт:
   - в MVP используются заглушки
   - пользователь выбирает вариант
   - дополнительные варианты добавляет админ через админку
