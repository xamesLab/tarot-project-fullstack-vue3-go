## Дополнительный аудит локализации сайта

Дата: 2026-10-19

### Что проверено

- Основные форматы дат и месяцев выбирают `ru-RU` / `en-US` по языку интерфейса.

### Найденные замечания

1. **P2 — английский текст во время загрузки на русской локали.** В `frontend/src/app/router.tsx` заглушки `ProtectedRoute`, `KeeperRoute` и `Suspense` показывают `Loading…` независимо от выбранного языка. В проекте уже есть локализованные строки загрузки в `common.json`, но эти маршруты их не используют. Рекомендация: вынести отображение загрузки в небольшой компонент с `useTranslation('common')` и использовать его во всех маршрутах.
2. **P2 — серверные сообщения ошибок отображаются без перевода в админке.** `getAdminError` в `frontend/src/features/admin/shared.ts` возвращает `error.message` напрямую; backend/API может вернуть текст на английском, который показывается пользователю на русской локали. Рекомендация: сопоставлять известные коды ошибок с ключами локализации, а для неизвестных показывать локализованный fallback; исходные детали оставить для диагностики.
3. **P2 — неизвестные ошибки авторизации могут показываться на языке сервера.** `AuthModal.tsx` переводит несколько известных ошибок, но для остальных ошибок 4xx возвращает `error.message`. Рекомендация: добавить отображение по коду ошибки и локализованный общий fallback.

Раздел UI Kit доступен только в dev-сборке; его русскоязычные демонстрационные подписи не относятся к пользовательскому production-интерфейсу.

### Итог

Покрытие ключей локализации полное, но отдельные временные состояния и ошибки всё ещё могут нарушать язык интерфейса. В этой проверке исходный код не изменялся; тесты и приложение не запускались.




### Решение по дополнительным замечаниям

Пользователь подтвердил, что английские заглушки загрузки и возможные англоязычные сообщения ошибок являются допустимыми отклонениями. Оставить поведение без изменений; рекомендации по этим пунктам не требуют выполнения.
